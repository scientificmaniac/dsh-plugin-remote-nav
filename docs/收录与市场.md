# 收录与市场资料

本文件对照 DSH 插件收录规范（awesome-dsh-plugin 的贡献指南），逐项说明本仓库的准备情况，
并给出可直接提交的收录条目。

## 1. 收录条件检查

| 要求 | 本仓库状态 |
| --- | --- |
| `package.json` 声明 `dsh.bundle` manifest（只声明 `dsh.client` 不可安装） | ✅ `dsh.bundle.patch` → `cordis.patch.yml`，宿主行 `remote-nav` |
| 真实可运行的代码，非占位 / 纯 README | ✅ 引擎、客户端插件与 16 项测试；预构建 `client.js` 随仓库提交 |
| 仓库创建满 1 天 | ⏳ 推送到 GitHub 后开始计算（本地 git 初始化时间不算） |
| 项目处于活跃维护状态 | ✅ 当前为测试版，持续迭代 |
| 仓库添加 `dsh-plugin` topic | ⏳ 推送后在 GitHub 设置，或执行 `gh repo edit --add-topic dsh-plugin` |
| 描述准确、无营销词 | ✅ 条目描述只陈述功能；README 与包描述同样只描述能力 |
| 分类贴合插件实际做的事 | ✅ 建议 `ui`（界面增强） |
| 图标为 GitHub 托管的位图 | ✅ `assets/icon-180.png`（180×180 方形 PNG） |
| 截图声明在本仓库内 | ✅ 根目录 `screenshots.json`（2 张：导航 HUD、侧边栏开关） |

| 发布 npm / Release tarball（可选） | ➖ 未发布；仓库已提交 `client.js`，从源码安装不需要构建步骤 |
| 一个 PR 最多 3 条 / monorepo 子包 | ➖ 单个插件 |

## 2. 可直接提交的收录条目

提交到 awesome-dsh-plugin 仓库时，新增一个文件 `data/plugins/<owner>__<repo>.yml`。
按本文档的预填地址，路径为 `data/plugins/scientificmaniac__dsh-plugin-remote-nav.yml`：

```yaml
url: https://github.com/scientificmaniac/dsh-plugin-remote-nav
name: scientificmaniac/dsh-plugin-remote-nav
category: ui
description:
  en: Remote-control and arrow-key spatial navigation for the DeepSeek Harness web UI.
  zh: 为 DeepSeek Harness Web UI 提供遥控器 / 方向键空间导航。
icon: https://raw.githubusercontent.com/scientificmaniac/dsh-plugin-remote-nav/main/assets/icon-180.png
```

> 如果最终使用的 owner/repo 不是 `scientificmaniac/dsh-plugin-remote-nav`，
> 请同步替换 `url`、`name`、`icon` 与文件名。

同一份内容也放在仓库的 [`docs/scientificmaniac__dsh-plugin-remote-nav.yml`](scientificmaniac__dsh-plugin-remote-nav.yml)，
可直接改名为 `data/plugins/scientificmaniac__dsh-plugin-remote-nav.yml` 提交到收录仓库。

注意事项：

- 只提交这一个文件；对方的两个 README 由脚本生成，**不要手工编辑**。
- 描述中若出现“冒号 + 空格”必须加引号；本条目没有该问题。
- `icon` 必须是 GitHub 托管的位图（png/jpg/webp），不要写 SVG 或第三方图床。
- 该 PR 不应修改其他条目。

## 3. 推送到 GitHub 后还需要做

1. 创建 GitHub 仓库（建议名 `dsh-plugin-remote-nav`），推送 `main` 分支。
2. 添加 topic：`gh repo edit --add-topic dsh-plugin`（或网页端 Settings → Topics）。
3. 从仓库创建日算起满 1 天后再提交收录 PR（对方 CI 会自动检查仓库年龄）。
4. 可选：发布 npm 时，在 `package.json` 增加 `repository` 字段指回本仓库；不发布不影响收录。
5. 可选：给 GitHub Release 附加预构建 tarball；当前仓库已提交 `client.js`，不附加也能从源码安装。

## 4. 安装方式确认

- 仓库根目录同时存在 `package.json`（含 `dsh.bundle`）与 `cordis.patch.yml`，符合 `dsh plugin add` 的要求。
- `client.js` 是构建产物且已提交，因此从源码安装不需要执行构建。
- 本地开发安装方式不变：

  ```js
  plugin_manager({ action: 'install_bundle', target: 'E:\\ai project\\小米遥控器兼容插件' })
  ```
