# 架构说明

本文说明这个插件为什么能工作、它依赖 DSH 的哪些契约，以及后续升级时要改哪里。

## 1. 只保留 DSH 内置插件

本项目只有一种接入方式：**DeepSeek Harness 的 profile bundle（内置插件）**。
没有油猴脚本、没有浏览器扩展、没有独立的页面脚本产物。

一个 bundle 由三部分组成：

| 文件 | 作用 |
| --- | --- |
| `cordis.patch.yml` | Loader 补丁：插入一行宿主插件（`remote-nav`） |
| `index.js` | 宿主侧 Cordis 入口，只保留占位 `apply()`，能力全部在客户端 |
| `client.js` | Web UI 客户端插件，`window.__ModuleLoader__` 工厂，由 DSH 客户端加载执行 |

客户端插件会在 Web UI 启动后加载，挂载导航引擎，并在侧边栏底部注册一个开关按钮。

## 2. 构建关系

```
src/remote-nav.js     核心引擎（零依赖，可单测）
src/dsh-autostart.js  页面侧引导：挂载 / HUD / 菜单键 / 诊断 / 可逆 destroy
src/dsh-client.js     客户端插件入口：apply、开关按钮、locale
src/remote-nav.css    高亮、HUD、开关按钮样式

scripts/build.mjs     去模块化拼接 → client.js（唯一构建产物）
```

`client.js` 是仓库的一部分，安装 DSH 插件时直接使用；改了 `src/` 必须重新 `npm run build`。
构建时不引入打包器：三份源码去掉 `import` / `export` 后拼进同一个工厂作用域，只通过
`require('react')` 获取宿主提供的 React。

## 3. 客户端插件生命周期

`client.js` 的结构：

```js
window.__ModuleLoader__.load({
  id: 'dsh-plugin-remote-nav', // 必须等于 package.json 的 name
  factory(require) {
    const React = require('react');
    // 引擎 + 引导 + 插件入口的源码
    return createClientPlugin(React); // { inject: ['slots'], apply(ctx) }
  },
});
```

- `apply(ctx)` 里通过 `ctx.effect(...)` 注册挂载逻辑并返回清理函数：
  - 挂载：键盘监听、高亮浮层、HUD、`window.dshNav` 全局别名；
  - 清理：移除监听器、HUD、注入样式、全局别名，并 `nav.destroy()`。
- 文案通过 `ctx.get('locale')` 注册中文字典并交由 slot 注册项注入；切换语言即时生效。
- 按钮注册点是 `sidebar.footer.action`：
  `ctx.slots.inject(name, () => ctx.slots.register({ ... }, withLocale(RemoteNavButton)))`。
- 卸载插件时，DSH 会执行 `ctx.effect` 的清理函数，因此不会残留监听器或 DOM。

## 4. 引擎与 DSH DOM 的协作方式

引擎**只读**业务 DOM，不修改业务节点（不写 `tabindex`、不换 class），高亮框和 HUD 是独立的
`position: fixed` 浮层，所以 React 重渲染不会破坏导航状态。

### 4.1 候选元素

默认选择器覆盖原生可交互元素、常见 `role`、`tabindex`、`contenteditable`，以及本插件认识的
`[data-composer-card]`。另外有三条排除规则：

| 规则 | 选择器 | 原因 |
| --- | --- | --- |
| 忽略整棵子树 | `[data-remote-nav-ignore]` | 插件自身的 HUD / 高亮浮层 |
| 只跳过元素自身 | `[data-disclosure-row]` | 聊天里的「思考 / 运行命令」等整行展开记录，不算导航目标 |
| 输入卡片特别处理 | `[data-composer-input]` | 文字输入区并入整卡大框，不单独占一个候选 |

DSH 的会话输入框结构（0.2.x）大致是：

```html
<div data-composer-card tabindex="-1">
  <div data-composer-input contenteditable="true" role="textbox"></div>
  <div>…底部按钮 + 权限 + 模型 + 麦克风 + 发送…</div>
</div>
```

因此：

- 整张卡片是**一个**导航目标，按 OK 时把焦点交给 `[data-composer-input]`；
- 卡片底部的按钮各自仍是独立候选；
- 左右移动不会跳进“包含当前元素的大框”，避免大框中心在右侧时遮住同一行按钮。

### 4.2 返回键分层

`_backAction()` 按顺序尝试：

1. 当前焦点在可编辑元素 → `blur()`，导航模式保持开启；
2. 存在可见的 `[role=dialog|alertdialog|menu|listbox]` → 向弹层派发一个带标记的 `Escape`（页面自己关闭它），导航保持开启；
3. 否则 → 退出导航模式。

### 4.3 会话滚动与长按加速

阅读会话时，方向键没有候选可去（或下一个候选是输入框）时，滚动最近的滚动容器，
首选 `[data-conversation-scroll]`。按住同一方向时用 `scrollForce(heldMs)` 从 1x 线性加速到
`scrollAccelMax`（默认 3x，约 900ms 到上限）。滚动期间进入“阅读滚动模式”，不会因为元素滚出
视口而突然跳到远处候选；滚到头再按同一方向，才把光标交给输入框。

### 4.4 会话打开后的输入框自动聚焦

DSH 在打开已有会话、或一轮回答结束时，会自动聚焦输入框。为了让遥控器仍然可用：

- 输入框里第一次按方向键先退出输入（`leaveEditingOnArrow`，默认开启）；
- 返回键在第一层也做同样的事。

## 5. 版本适配

引擎依赖以下 DSH 0.2.x 的 DOM 约定；如果未来版本改字段名，只需要改
`src/remote-nav.js` 里 `DEFAULTS` 的对应选择器：

| 选择器 | 用途 |
| --- | --- |
| `[data-composer-card]` | 会话输入卡片（整卡一个目标） |
| `[data-composer-input]` | 卡片内的文字输入区 |
| `[data-composer-seat]` | 输入框座位（备用） |
| `[data-conversation-scroll]` | 会话滚动容器 |
| `[data-disclosure-row]` | 聊天记录展开行（默认跳过） |

除此之外，引擎只依赖通用 DOM API：`querySelectorAll`、`getBoundingClientRect`、
`MutationObserver`、`scrollBy`、`focus` / `click`。
